# Архитектура

`default.xex` → ReXGlue static codegen → C++23 → clang++/LLD → Windows x64 EXE.
ReXGlue runtime обеспечивает гостевую память, PPC context, kernel/XAM imports,
потоки, VFS, аудио и ввод. Xenos plugin исполняет GPU-команды через D3D12.
Xenia используется только как будущий эталон исследования, а не процесс
или скрытый backend конечного приложения.

Главный код не заменён имитацией. `Cod3pcApp` наследует официальный `ReXApp`.
`src/runtime/entry_trace.cpp` оборачивает фактический символ `xstart`
(гостевой адрес `0x82344D00`) и передаёт исходный PPC context в
`__imp__xstart`; не меняет игровое состояние.

VFS монтирует `assets/game` как `game:` и `d:`. Сохраняется исходная структура
`media`, `sp`, `mp`. Данные имеют big-endian PPC представление; чтение и
запись остаются в механизмах SDK. Собственные пустые kernel stubs запрещены.

Обнаружены 15 настоящих XEX DLL в `sp/<level>/<level>.dll`.
Их нельзя загрузить как обычные Windows PE DLL. Для кампании нужны
отдельные `[[modules]]`, codegen и registry SDK. Они пока не включены в
entrypoint-проект; MP `codmp_xenonf.xex` отдельно и вне первичного объёма.

Пока не установлены реальные зависимости ресурсов, NGL init/frame функции,
графические отклонения, аудиокодеки WBK и контракт сохранений. Формат `.cod`
не объявляется аналогом CoD4 без исследования. Расширения и сигнатуры
являются только инвентаризацией, не доказательством семантики файлов.
