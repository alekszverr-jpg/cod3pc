## Что подтверждено исходниками и что заявлено

[README](https://github.com/zenit2893-cmyk/project-1944/blob/62ab3b08e4db1a5f21fb0c13b49d4a3ebd004812/README.md)
описывает сборку 15 DLL, но отмечает проверку преимущественно Saint-Lo,
а не полное прохождение кампании. Состав сборки не является доказательством
стабильности всех миссий. Поддерживаемый default.xex hash совпадает с нашим;
любые адреса и ABI всё равно требуют проверки по нашему оригинальному образу.

| Возможность | Что включаем в наш план | Критерий принятия |
|---|---|---|
| Мышь с прямым обновлением камеры | Raw mouse look, чувствительность, инверсия, масштабирование ADS/FOV | Нет ускорения/потолка стика и двойного поворота; одинаковое движение мыши при разных FPS; корректные ADS и контузия |
| PC-раскладка | Переназначение, отдельные crouch/prone, hold/toggle ADS, колесо и боковые кнопки | Нет залипания при потере фокуса; совместимость с XInput и переключением устройств |
| Меню с мышью | Hover, click, wheel, правильный захват/освобождение указателя | Диалоги и пауза получают ввод; щелчок по меню не вызывает выстрел после закрытия |
| Подсказки PC | Собственные иконки клавиш/мыши, переключение по устройству | Обучение, взаимодействия и QTE показывают действующий способ ввода; оригинальные assets на диске не редактируются |
| QTE с мышью | Вращение, раскачивание, борьба, гребля; отдельная настройка помощи | Проверить реальные сцены, обе стороны стиков, направление и частоту кадров; геймпад сохраняет исходное поведение |
| Пропуск роликов | Безопасный skip после готовности загрузки уровня | Брифинг не обрывает незавершённую загрузку; повторный запуск/skip сохраняют состояние миссии |
| Изображение | Сохранение DoF, разрешение, fullscreen/windowed, render scale, vsync | Проверить HUD/мышь/поля кадра, depth/EDRAM, перезапуск и расход GPU памяти |
| Режимы 60/120 Гц | Настройка ограничения кадров и измерение времени CPU/GPU | Проверить скорость игры, AI, анимации, физику и QTE; отсутствие мерцания между simulation/render кадрами |
| Лаунчер | Профили настроек, импорт собственной копии, проверка hash, продолжение установки | ISO/распакованная папка/GoD; понятные ошибки; отмена без потери уже обработанных файлов |
| Диагностика | Console/script logs, frame p50/p95/p99, ограничение размера логов, локальный отчёт | Воспроизводимые сцены и bounded overhead; отчёт не содержит assets, generated game code, saves или секретов |
| Геймпады | SDL/HIDAPI для устройств вне XInput | Проверка подключений, раскладок, QTE и возврата к мыши |

## Переходы кампании — отдельный технический приоритет

Исходник
[title_relaunch.cpp](https://github.com/zenit2893-cmyk/project-1944/blob/62ab3b08e4db1a5f21fb0c13b49d4a3ebd004812/integration/pc-controls/title_relaunch.cpp)
реализует новый native-процесс с передачей launch data, несмотря на формулировку
README о переходах внутри host. Комментарий описывает 664 байта состояния
и исходный XamLoaderLaunchTitle. Это полезная гипотеза для нашего закрытия окна
после Saint-Lo; сам механизм у нас ещё не проверен и не перенесён.

Сначала снять наш реальный переход с COD3_TRANSITION_* и подтвердить исходные
launch-data вызовы/размер. Если движок требует reboot, реализовать передачу
его состояния через штатные SDK contracts с контролируемым перезапуском
native host. Должны сохраняться checkpoint, текущая миссия и настройки;
не должно возникать три игровых процесса/окна. DLL load/unload и освобождение
script continuations проверяются отдельно от эффекта бесшовного окна.
